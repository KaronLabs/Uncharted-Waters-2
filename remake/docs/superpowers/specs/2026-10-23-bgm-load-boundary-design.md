# BGM·불러오기 경계 연관 결함 수정 설계

## 요청과 현재 기준

사용자는 BGM 중첩 수정에 이어 RED-ALPHA로 연관 결함의 병렬 조사·조치와 검증 범위 선정을 요청했다. 기존 중첩 수정 소스는 57d4c62e865e7332d2b0b5a16fc7eb4d1091f33e이며 아직 원격 배포하지 않았다. 기존 v0.3.0 EXE에서는 UI 불러오기 직후 활성 BGM 2개를 독립적으로 재현했다.

## 권장 접근과 대안

- 권장: 기존 Sound 컴포넌트와 저장 로더에 결함별 최소 수정을 적용한다. 오디오 수명은 컴포넌트가 소유하고 기존 loadGeneration으로 낡은 응답을 거절한다. BGM 설정은 기존 브라우저 저장소 방식으로 별도 보존한다.
- 대안: 전역 오디오 엔진과 저장 요청 큐로 재구성한다. 이번 세 결함에 필요한 범위를 넘어 파일·상태·회귀 위험이 늘어나므로 채택하지 않는다.
- 사용자는 이 설계를 승인하고 관련 결함을 함께 수정하도록 선택했다. BGM 음소거는 불러오기·새 게임·앱 재실행 후에도 기억한다.

## 수정·검증 범위

| 경계 | 기대 동작 | 판정 방법 |
| --- | --- | --- |
| 불러오기·새 게임·컴포넌트 제거 | 기존 BGM을 정지·해제하고 활성 루프는 최대 1개 | 기존 EXE 중첩 재현, 단위 RED→GREEN, 새 EXE 활성 수·시각 진행 |
| BGM 음소거 후 불러오기·새 게임 | 사용자가 끈 음악이 다시 켜지지 않음 | 음소거 상태에서 remount 및 실제 Load/슬롯 Load; 앱 재실행 보존도 권장 |
| 같은 곡을 쓰는 건물·항구 이동 | 곡을 처음부터 재시작하지 않음 | src 재할당 없음 및 실제 currentTime 연속 증가 |
| 다른 곡을 쓰는 저장 슬롯 | 로드한 위치의 곡 하나만 재생 | 마을·주점의 서로 다른 실제 곡을 반복 왕복 |
| native read 응답 중 다른 Load/새 게임 | 이전 상태에 속한 응답이 새 상태를 덮지 않음 | 지연된 bridge 응답으로 RED→GREEN; 정상 read·실패 read도 확인 |
| 빠른 입력·재생 요청 중 취소·autoplay 차단 | 고아 음악·무처리 rejection·중복 listener 없음 | 재현 가능한 오류를 먼저 분류하고 확인된 결함만 수정 |

## 파일 경계와 책임

- Sound.tsx 및 Sound.test.tsx: BGM 수명·음소거·같은 곡 유지.
- desktopSlotStorage.ts 및 해당 테스트: 낡은 native read 응답 거절.
- DesktopSlots.tsx 및 해당 테스트: 취소된 오래된 요청의 안내가 현재 화면을 덮지 않도록 필요 시 최소 수정.
- scripts/verify-bgm-load.cjs: 실제 EXE UI 조작과 읽기 전용 미디어 관찰.
- 총괄: 구현 순서·파일 소유권·검증 통합·Git·EXE·GitHub 게시. 조사 에이전트는 승인된 파일 이외를 변경하지 않는다.

## 성공 기준과 제외 범위

- 단위 회귀는 수정 전 실패를 확인하고 수정 후 통과시킨다. 반례·취소·오류 입력도 포함한다.
- 최종 소스에서 npm run verify, 관련 데스크톱 검사, Windows 포터블 빌드가 통과해야 한다.
- 최종 EXE에서 정상 UI 저장·불러오기, 서로 다른 곡, 음소거 유지, 활성 BGM 1개와 종료 코드 0을 확인한다.
- 사용자 슬롯은 건드리지 않고 별도 프로필·슬롯으로 검사한다. 같은 EXE의 크기·SHA256·제품 소스 커밋을 고정한다.
- 기존 조안편 사용자 인수는 v0.3.0의 근거로 보존한다. 이번 소규모 회귀를 전편 완주나 실제 스피커 청감의 새 증거로 표현하지 않는다.
- 게임 규칙·항해·전투·다른 주인공·DOS 저장 포맷을 변경하지 않는다. 새 의존성·전역 엔진·일반 요청 큐를 추가하지 않는다.
- 최종 결과는 v0.3.1 수정판으로 main·다운로드·README에 맞춘다. 기존 v0.3.0 EXE와 증거는 보존한다.

## 조사 후 구체화한 동시성 정책

동시에 여러 native load가 시작되면 마지막 요청만 상태를 적용한다. 요청 당시 loadGeneration과 최신 요청 번호를 모두 확인한다. 일반 Load 또는 새 게임으로 generation이 바뀌면 대기하던 native 응답은 취소한다. 취소와 실제 실패를 UI에서 구분해 낡은 실패 알림이 현재 성공·새 게임 알림을 덮지 않게 한다. 같은 컴포넌트의 알림 타이머는 새 알림으로 교체하고 unmount 때 정리한다.
