| 새 항해 안내가 remount로 사라짐·옛 타이머가 새 안내를 지움 | 안내를 기존 부모 callback으로 전달하고 메시지 타이머 교체·해제를 수행. 새 EXE에서 새 항해 직후 한국어 성공 안내도 확인 |

### 실패·관측 범위도 보존합니다

- 최초 두 번의 최종 EXE 시도는 Load 2회 뒤 검증용 `portPalette` 이미지 관찰에서 `Runtime.evaluate` 시간 초과로 **FAIL**했습니다. [시도1](v0.3.1/evidence/native-attempt1-events.jsonl)·[시도2](v0.3.1/evidence/native-attempt2-events.jsonl)를 통과 기록에 합산하지 않습니다. 두 경우에도 앱 종료는 0이었습니다.
- 단독 이미지 관찰 및 일반 UI Load 진단은 통과했습니다. 검증 도구가 각 실행에서 `Page.bringToFront`로 창을 앞으로 가져오고 visible/focus를 확인한 뒤 전체 검사는 통과했습니다. **이전 시간 초과의 원인이 포커스였다고 확정하지 않습니다.** 제품·EXE·시간 제한·판정 조건은 바꾸지 않았습니다.
- 실제 EXE의 Audio 상태를 읽은 결과이며 물리 스피커 출력을 측정하지 않았습니다. 진단 수집은 각 CDP 연결 이후입니다. 100ms 목표 표본 사이의 더 짧은 현상이나 경계 inventory 사이 잠깐 생성·해제된 추가 객체는 관찰 밖일 수 있습니다.
- 빠른 실제 UI 입력은 의도적 native 응답 역전이나 pending play를 재현했다는 증거가 아닙니다. 해당 순서 경계는 별도의 deferred 단위 테스트가 검증합니다.
- 이번 패치에서 전편 여정·실제 OS 한글 IME·오프라인 글꼴 전체를 다시 검사하지 않았습니다. 이전 결과를 새 결과처럼 합치지 않습니다.

## 공식 문서 교차 확인

2026-10-24 Context7로 React 공식 문서를 조회하고 브라우저 미디어·Electron 공식 문서를 직접 대조했습니다. 문서는 API 동작의 근거이며, 제품에서의 해결 여부는 위 실패 재현과 EXE 실행으로 판단합니다.

- [React useEffect](https://react.dev/reference/react/useEffect): unmount 정리 및 개발 StrictMode의 setup/cleanup 반복에 맞춰 Audio와 입력 listener의 수명을 관리합니다.
- [MDN HTMLMediaElement.load](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/load): 리소스 재선택은 진행 중 미디어 작업과 pending play를 취소할 수 있어 AbortError 경로를 분리합니다.
- [MDN HTMLMediaElement.play](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play): 실제 재생 시작은 Promise 결과로 판단하며 NotAllowedError를 다룹니다.
- [Electron BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window): 창 가시성과 백그라운드 animation/timer 정책이 존재합니다. 이 일반 정책만으로 이번 관찰 타임아웃 원인을 단정하지 않습니다.
- [Chrome DevTools Protocol Page](https://chromedevtools.github.io/devtools-protocol/tot/Page/#method-bringToFront): 검사 창을 앞으로 가져오는 명시적 UI 전제에 사용합니다.

## 통합 판단과 남긴 경계

1. 마지막 native 요청이 우선하며 성공한 일반 Load/새 게임은 이전 native 응답을 취소하도록 정했습니다. 반대 정책이 필요하다면 취소 의미가 달라집니다.
2. 새 항해 안내와 메시지 타이머는 같은 불러오기 수명 문제로 포함했습니다. 게임 규칙·저장 형식은 바꾸지 않았습니다.
3. autoplay 거절은 조건부 코드 경로로만 재현했습니다. 실제 EXE의 관측 결과보다 넓은 해결 주장을 하지 않습니다.
4. 사용자의 수정·반영 요청과 승인 설계에 따라 main/Latest에 v0.3.1을 게시하며 v0.3.0 자산은 보존합니다. 새 주인공 구현은 하지 않습니다.
5. `playAudio`는 성공 true/예상 취소 false를 반환하도록 변경했고 유일한 제품 호출부와 테스트를 함께 갱신했습니다. 향후 호출부가 늘면 이 계약을 지켜야 합니다.

[독립 검토](v0.3.1/review.md)는 제품 변경·검증기에서 Critical/Important 0건을 확인했습니다. 기존 비동기 **저장**이 unmount 후 응답하면서 사라진 컴포넌트에 로컬 안내 타이머를 만들 수 있는 경로는 이번 native **불러오기** 취소와 다른 기존 문제로 남겼습니다. 현재 게임 상태나 부모 불러오기 안내를 덮는 반례는 아니며, 관련 없는 저장 흐름 재설계를 추가하지 않았습니다.
