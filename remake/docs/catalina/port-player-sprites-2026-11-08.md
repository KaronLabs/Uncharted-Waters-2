# 카타리나 Windows 인수 후보: 항구에서 주인공별 모습으로 걷기

카타리나로 시작해도 조안이 대신 걸어 다니던 버그를 고쳤습니다. **이번 배포는 카타리나 사전 릴리스 후보**입니다. 조안 정식판 `v0.3.1`과 GitHub `Latest`는 그대로이며, 카타리나 전편 사용자 실플레이 인수와 다른 네 주인공의 전편 완주는 이번 수정의 완료 판정에 포함하지 않습니다.

## 원인과 수정 경계

주인공 선택과 저장된 `protagonistId`는 정상인데, 항구 렌더러가 플레이어를 항상 `portCharacters.png`의 첫 8프레임으로 그렸습니다. 이 첫 8프레임은 조안이고 뒤의 24프레임은 NPC입니다. 한글판 원본에서 추출해 이미 저장소에 있던 `char0`~`char5` 중 선택한 주인공의 이미지를 **플레이어에게만** 사용하게 바꿨습니다. NPC 이미지·프레임 번호, 이동·충돌, 저장 형식은 그대로입니다.

| 선택한 주인공 | 마을에서 사용할 원본 이미지 |
| --- | --- |
| 조안 | `char0` |
| 카타리나 | `char1` |
| 오토 | `char2` |
| 에른스트 | `char3` |
| 피에트로 | `char4` |
| 알리 | `char5` |

## 검증 결과와 범위

- 수정 전 렌더링 재현 테스트: **조안 1건 통과, 나머지 5건 예상 실패**. 수정 후 6건 모두 통과하고 NPC가 기존 이미지를 쓰는 것도 확인했습니다.
- `npm run verify`: **127 suites / 1,109 tests 통과**, Windows 슬롯 검사 **4/4**, 형식·타입·린트·웹 번들 빌드 종료 코드 0. 새 이미지 5개가 번들에 포함됐습니다.
- 데스크톱 위치 탐색 관련 검사: **42/42 통과**. 주인공 전환 시 이전 이미지의 탐색 캐시를 버립니다.
- 위 해시의 **새 EXE**를 격리 프로필·시험 슬롯에서 실행했습니다. 여섯 주인공 모두 새 게임, 실제 마을 이동 1회 이상, Windows 시험 슬롯 저장→다른 주인공 시작→불러오기 뒤에 원본 이미지와 화면 픽셀이 **일치율 1.0**이었습니다. 카타리나는 네 방향의 걷기 프레임 **0~7 전부** 확인했습니다.
- 음성 대조로 이전 EXE(`fe549e03e31e1fd3bdd84e7824291f75360f8ded23f60ae07eaae945526edccc`)를 같은 검사에 넣었을 때 카타리나 화면의 이미지 일치율은 **0.385**로 실패했습니다. 새 EXE와 이전 EXE의 결과는 합산하지 않았습니다.
- 검증 스크립트는 형님의 슬롯을 읽기 전·후 SHA256으로 대조했고 **변화가 없었습니다**. 공개 ZIP에는 시험 프로필·슬롯·로컬 절대 경로를 넣지 않고 결과 JSON과 화면 26장만 실었습니다.

이 검사는 **항구 캐릭터 이미지 수정의 검증**입니다. 카타리나 전편 실플레이, 다른 네 주인공의 전편 내용, 실제 Windows 150% 배율 검사는 새로 통과한 것으로 표시하지 않습니다. 이전 후보의 제목·여정 검증 기록은 [당시 문서](title-update-2026-11-08.md)와 [카타리나 인계 보고서](completion-report.md)에 그대로 남겼습니다.
